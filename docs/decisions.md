# 설계 결정

## 문제와 범위

검사 예약 담당자가 의뢰서·연락처 확인·사전 확인표의 접수 여부와 검사실 가용 시간을 따로 확인하는 업무를 합성 사례로 구성한다. 실제 병원의 시간 절감 효과를 측정한 것은 아니다. 임상 판단은 범위 밖이다.

## 두 에이전트가 필요한 이유

준비 확인 담당자는 행정 규칙과 의뢰 상태를 해석하고 오전·오후 선호를 추출한다. 일정 조정 담당자는 가용 시간과 선호 조건을 근거로 후보를 선택한다. 준비 미완료 시 일정 조회로 진행하지 않는 책임 경계를 갖는다. 배포 단위는 하나로 줄이되 HTTP A2A 계약을 통해 향후 분리 가능하게 한다.

## 프로토콜과 배포

A2A 0.3 SDK를 정확한 버전으로 고정한다. 최신 1.0 기능을 사용한다고 주장하지 않는다. 자체 함수 호출을 A2A로 표기하지 않고 공식 SDK 서버와 HTTP 클라이언트를 사용한다. MCP는 공식 SDK stdio 전송으로 별도 프로세스 도구를 호출한다. Cloud Run 단일 인스턴스 데모로 운영하고 SQLite의 휘발성 및 확장 한계를 문서화한다.

## 모델과 코드

모델은 요청 해석·근거 요약·허용 후보 선택을 맡는다. 누락 필드와 후보의 적법성, 승인 상태, 중복 확정 및 슬롯 충돌은 코드가 검증한다. 테스트 fixture 모드는 재현성용이며 실제 모델을 호출한 것처럼 표시하지 않는다.
